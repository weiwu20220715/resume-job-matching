# 机械类学生简历诊断与岗位匹配原型

本程序是机械类学生简历诊断与岗位匹配的本地原型。它把学生简历中的**书面证据**与岗位要求逐项比较，生成简历修改建议、岗位排序和可编辑的 Word 报告。项目申报书只保存在原电脑，不纳入 Git 仓库；程序运行不依赖该文件。

## 1. 当前能完成什么

1. 上传可提取文字的 PDF、DOCX、TXT 简历，或直接粘贴简历文字。
2. 导入企业岗位 CSV，或粘贴单个岗位说明并补充学历、专业、技能、工具、职责和项目要求。
3. 提取学历层次、专业、专业技能、工具应用、工作或实习职责、项目经历与成果线索。
4. 显示每个岗位维度的已找到证据、未在简历中找到的要求及匹配度。
5. 对有足够事实的原句给出“原句—问题—建议替换句”；事实不足的句子列出需要核实的内容，不生成虚构经历。
6. 逐维度说明简历中已展示的优势、待改进之处、覆盖率与原句证据，生成 Word 报告及 JSON 数据。

程序不调用云端模型，不把简历主动发送到外部服务。当前的文本识别、术语归一和评分是**可解释的本地原型规则**，适合演示、收集反馈和继续完善，不可把分数解释为学生实际能力、就业竞争力的最终测量值或录用概率。

## 2. Windows 启动步骤

**推荐：双击[启动程序.bat](启动程序.bat)。** 它直接打开中文桌面窗口。新界面用 PySide6 构建，采用浅色背景、侧边导航、卡片和清晰的指标区。这个启动器固定使用当前电脑已验证的 `D:\Anaconda\pythonw.exe`；如果 Anaconda 安装位置以后改变，请同步修改启动器中的 `PYTHONW_EXE`。其他电脑安装依赖时运行 `python -m pip install -r requirements.txt`。

如果需要在终端查看错误，在本文件夹执行：

```powershell
& 'D:\Anaconda\python.exe' desktop_app.py
```

原有的本地网页版仍可通过[启动网页版.bat](启动网页版.bat)打开，通常访问 `http://localhost:8501`。网页版和桌面版使用相同的简历分析与报告代码。第一次运行网页版时的英文邮箱提示已在项目配置中关闭。

## 3. 使用顺序

1. 上传简历。建议先移除身份证号码、手机号、详细住址等非必要个人信息，并用匿名编号生成报告。
2. 首次体验可保留 5 个演示岗位。正式分析时取消勾选，导入**真实企业岗位** CSV；模板位于[data/jobs_template.csv](data/jobs_template.csv)。
3. 岗位 CSV 每行一个岗位，表头为：`岗位名称,企业名称,最低学历,相关专业,专业技能,工具软件,工作职责,项目关键词,岗位描述`。同一字段的多个要求使用顿号、逗号或分号分隔。`最低学历` 使用 `中专/大专/本科/硕士/博士`。
4. 在岗位列表选择重点分析岗位，点击顶部“开始分析并生成报告”。程序会立即完成分析并生成内存中的 Word 报告。到“匹配分析”查看各维度覆盖率与优劣势，到“修改建议”查看原句与建议替换句，最后在“报告导出”页面保存 Word 文件。
5. 对报告中所有“未在简历找到”的项，先问学生是否有真实经历；有则补充具体证据，没有则列入后续学习或实训计划。

手动粘贴岗位说明时，系统仅自动识别词典中已有的学历、专业、技能和工具词；请核对自动结果，并主动填写“工作职责关键词”“项目经验关键词”。CSV 导入方式更适合正式岗位库。

## 4. 分数怎么算

默认维度及演示权重：学历 10%、专业 10%、专业技能 30%、工具应用 20%、工作职责 15%、项目经验 15%。某个岗位没有填写的维度不参与评分，其余维度按比例重新归一。

每个维度的覆盖率按“简历中找到的要求条目数 ÷ 岗位要求条目数”计算。学历和专业按最低学历与相关专业匹配。最终分数为各维度覆盖率的加权和。工作职责只在实习/工作与项目栏目查找；项目经验只在项目栏目查找，减少单纯罗列关键词的误判。页面会显示每个条目对应的简历原句。岗位至少需包含 3 个不同的技能、工具、职责或项目要求才会评分；要求不足的岗位会标为“未评分”。不同岗位要求的完整程度仍会影响跨岗位比较。**工具或技能只被罗列，即使关键词覆盖率高，也会在“应用深度”中提示缺乏项目证据。**

“优势”指当前文本对岗位要求覆盖较高或有成果线索；“待改进”指书面证据缺口和表达深度问题，均不代表学生真实能力强弱。逐句替换基于本地规则，只改写原句已给出的事实；若原句仅写“熟悉/了解/负责”，缺少具体项目或交付物，程序会要求补充事实，不会自行编造一条看似完整的新经历。

例如岗位需要 4 个技能，简历中可找到 2 个，该维度覆盖率为 50%。这只说明**简历目前展示了 2 项证据**。学生可能掌握其余技能但没有写，也可能只是写了关键词而缺少实践深度，所以最终仍需面谈和材料核实。

## 5. 数据与验证边界

当前仓库没有真实企业岗位库、专家评估数据或学生试点数据，因此附带的 5 个岗位均明确标注为**演示样例**。本程序已打通上传—解析—建议—报告—匹配流程；以下内容仍需在项目后续工作中完成：

- 经企业访谈或招聘资料核对，建设可追溯的真实岗位库。
- 通过专家论证和学生样本校准词典、指标、权重与匹配阈值。当前权重是开发用演示值。
- 建立人工标注集，对信息提取、建议质量和岗位排序分别测评。当前**没有实测准确率**。
- 增加扫描版 PDF 的 OCR、成绩单/证书证据、多义词消歧与基于上下文的深层中文表达优化。当前逐句建议是本地规则，无法替代人工编辑和事实核实。

## 7. 测试与常见问题

在本文件夹执行：

```powershell
python -m pytest -q
```

- **扫描版 PDF 提示提取不到文字**：先用 OCR 把它转成可复制文字的 PDF 或 DOCX；本程序不会猜测图片中的内容。
- **分数明显偏低**：查看“未在简历找到”的具体要求，先确认栏目标题是否标准、术语是否不同写法、岗位要求是否过于笼统。
- **图表中文显示为方框**：Windows 通常有微软雅黑；其他系统需安装中文字体或在 `reporting.py` 中指定本机字体。
- **岗位说明只粘贴原文后维度不完整**：手动补充结构化字段，或使用 CSV；自动词典提取只覆盖已收录的术语。
- **同一学生信息不想留存**：本程序默认没有数据库；关闭程序并自行管理或删除已保存的 Word/JSON 文件即可。
- **双击后没有桌面窗口**：在项目文件夹运行 `& 'D:\Anaconda\python.exe' desktop_app.py`，查看终端报错；再检查 `D:\Anaconda\pythonw.exe` 与 PySide6 是否存在。
